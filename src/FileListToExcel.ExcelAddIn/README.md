# Native Excel integration

This optional x86/x64 native COM add-in implements IDTExtensibility2 with a static C++ runtime. It uses the Application supplied by Excel OnConnection; it never attaches to an arbitrary active Excel instance. No VBA, VSTO, Office PIA, developer SDK, script host, or downloaded runtime is required on user computers.

MSI owns ProgID FileListToExcel.ExcelAddIn and CLSID {0B1E297C-42CC-48A4-A973-3AA8EAF26795}. The 32-bit and 64-bit COM registry views point to separate DLLs in the product install directory. Both invoke the existing x64 helper. The Explorer CLSID is separate. The optional ExcelIntegration feature is not selected by default, including upgrades from releases without this feature. A feature tree explains the choice during interactive setup. Save work and restart Excel after adding/updating/removing the feature.

OnConnection installs temporary controls in Cell and List Range Popup CommandBars, using product-specific ownership tags. Button clicks are compiled connection-point callbacks; there is no OnAction macro. Only this product's exact tags are removed. The application SheetBeforeRightClick callback checks Target against the actual Selection; capture always uses the complete Selection, never Target alone. Disconnect releases subscriptions, controls and COM references. No monitor re-enables a disabled add-in.

The command reads supported properties and tables from the current, potentially unsaved workbook. It intersects one registered FileListTableN with selected areas, respects filtered/manually hidden rows, deduplicates row numbers and bounds the capture to 10,000 visible rows/32 MiB. Same-table technical columns follow sorting. The helper revalidates all bounded source JSON, ItemId, visible name/path, version and real filesystem state. Format markers are not authentication. No filesystem/network source validation occurs when preparing menus.

A random GUID request uses the existing private per-user spool/DACL pattern. Ancestor directories are pinned and checked against reparse/recall attributes before writing. Failed writes are deleted by their original open handle; failed helper launch may retain its random request for diagnosis rather than deleting a replaceable pathname. No shell command interpreter is used. A process handle prevents duplicate clicks within the connected Excel instance; the handle is released on completion or disconnect. Helper lifetime is bounded to the selected operation.

Build/test through scripts/Build.ps1. Native tests cover COM exports/class factory/refcounts and request identity on x86 and x64; they do not establish actual Office compatibility. The actual Excel startup/selection/copy harness and results belong to the integration validation record. Windows logon/reboot, clean user, x86 Office, managed add-in policies, and other vendors' add-ins require explicit environmental testing.

Read-only diagnostics: scripts/Get-ExcelIntegrationStatus.ps1. A registry/DLL check cannot prove that Excel accepted and connected an add-in. Missing Office, missing payload, wrong PE architecture, disconnected/disabled state and policy evidence are reported separately. Never lower Trust Center, macro, add-in, signature or organization settings to make a test pass.

Excel SDI lifecycle: menu refresh reacquires the active workbook window's exact-tag controls and subscribes each canonical COM button identity once. Sheet edits, selection, workbook open/activation and window activation refresh availability. Closed-window bindings are unadvised; disconnect removes only recorded owned menus. Callback operations retain the add-in and defer teardown until the outermost operation returns, including a disconnect during an outgoing Excel call. The start screen can connect before a workbook or CommandBars exists; application events prepare menus when a workbook opens.

The native two-window mock regression checks start-screen connection, newly cloned control callback wiring, disabled unsupported-workbook state, repeated-event deduplication, by-reference right-click Target, closed-window cleanup and reentrant disconnect. Actual Office behavior remains a separate integration gate. This follows Microsoft's [Excel SDI guidance](https://learn.microsoft.com/en-us/office/vba/excel/concepts/programming-for-the-single-document-interface-in-excel). Event DISPIDs were checked against the installed Excel type library; no Excel process is launched by that inspection.

The native selection regression invokes the real Capture automation path against bounded IDispatch range fixtures. It covers row deduplication/order across Ctrl selections, filtered/hidden row exclusion, whole-sheet intersection before metadata reads, all-hidden/header-only/unrelated selections, missing technical columns, formula/duplicate identities, and the 10,000-row preflight limit. These mocks exercise request construction; they do not replace real Excel selection and UI acceptance.
